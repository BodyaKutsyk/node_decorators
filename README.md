# Саморобний (майже) Dependency Injection Container + Inject/Injectable decorators

## Як запустити
- Для запуску потрібно виконати команду `npm run start`.
- Для тестування потрібно виконати команду `npm run test`

Проєкт працює на двигуні виконання `ts-node`, тестується через нативну бібліотеку `node:test`.

## Принцип роботи:
1. Будь-який декоратор емітить метадані класу у глобальний об'єкт `Reflect` через `defineMetadata("design:paramtypes", value, target)`. Це відбувається завдяки поліфілу `reflect-metadata` та поведінці TypeScript декораторів при:
```` ts
{
    "compilerOptions": {
        "experimentalDecorators": true,
        "emitDecoratorMetadata": true,
    }
}
````
2. Так як типи Typescript у метаданих `Reflect` перетворюються в `Object`, було додано додаткове поле метаданих `design:paramtoken` через декоратор `Inject(token)`.: 

```` ts
    class TransactionService {
        constructor(@Inject(TYPES.logger) private readonly logger: Logger) {}
    }
````
Через додаткову властивість метаданих наведеного прикладу, можна підказати DI контейнеру, що конструктор класу очікує аргумент, на який буде посилатися токен 
3. Декоратор `Injectable()` додає метадані для класу, позначаючи його ін'єкційним для контейнера та може містити додаткові властивості як `scope`
4. Dependency injection контейнер реалізовує два методи: `bind` та `resolve`.

Метод `bind` слугує провідником між наданим раніше токеном і класом, за яким ми хочемо зробити ін'єкнцію.

Метод `resolve` займається власне генерацією екземпляра на основі отриманих залежностей через `@Inject(token)`. У цей метод входять такі перевірки перед побудовою екземпляру:
1. перевірка на циклічність: `A -> B -> A` поверне помилку **Circular dependency**
2. перевірка чи наданий клас має `Injectable()` метадані, поверне помилку **`target.name` is not `Injectable()`**

Після наведених вище перевірок метод починає діставати параметри з `Reflect.getMetadata` і рекурсивно проходитися по кожному параметрі. Кожен параметр перевіряється на наявність додаткових метаданих `design:paramtoken`. Якщо метадані (індекс, токен) є, то відбувається один з двох сценаріїв:
1. У контейнера немає інформації до чого прив'язаний цей токен, то контейнер кине помилку `No binding found for token`
2. У контейнера є інформація про токен і до чого він прив'язаний, у рекурсію надається отримане значення за токеном

Якщо ж метаданих `design:paramtoken` немає, то у рекурсію передається аргумент з ітерованого значення метаданих `design:paramtypes`

Під час кожної ітерації відбувається перевірка на `scope` з `Injectable`.1 Якщо `scope === 'singleton'` і такий екземпляр вже було згенеровано контейнером, то контейнер повертає раніше створений екземпляр.
Якщо ж `scope === 'transient'`, то кожен раз створюється новий екземпляр.
